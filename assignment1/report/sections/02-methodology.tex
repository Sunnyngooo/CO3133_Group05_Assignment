\subsection{End-to-End Deep Learning Pipeline}
\subsubsection{Pipeline Overview}
The project separates configuration, data preparation, model construction, optimization, prediction, evaluation and checkpoint management~\cite{code}. The five models share this infrastructure. Training updates model weights, validation selects the checkpoint, and the final test only evaluates the selected model.
Figure~\ref{fig:method-pipeline} separates weight updates from validation/test prediction. Preprocessing uses the saved split and training-derived normalization; a model maps $B\times1\times28\times28$ images to $B\times10$ logits. Prediction takes the largest logit; no additional class post-processing is applied.

\subsubsection{DataLoader, Training and Evaluation}
Separate dataset objects provide independent training and validation transforms while referring to disjoint saved indices. The training loader shuffles with a seeded generator; validation and test retain their order. Batch size is 128 and \texttt{num\_workers=0}. Each training batch clears gradients, computes logits and cross-entropy, backpropagates and performs one optimizer step. Training enables dropout; validation and test disable it with evaluation mode and gradient suppression.

Epoch loss is sample-weighted: for batch size $n_b$ and mean batch loss $\ell_b$,
\begin{equation}
\bar\ell=\frac{\sum_b n_b\ell_b}{\sum_b n_b}.
\end{equation}
Thus the final partial batch is not weighted as heavily as a full batch. Accuracy and Macro-F1 are computed from the entire epoch's prediction vectors rather than averaged over batch scores. Evaluation rebuilds the architecture from the saved YAML, loads its selected checkpoint and exports test metrics. Error analysis separately verifies that its Accuracy and Macro-F1 agree with the saved test record.

\subsubsection{Linear / Softmax Classifier}
The baseline flattens the image to $v\in\mathbb R^{784}$ and computes
\begin{equation}
z=Wv+b,\qquad W\in\mathbb R^{10\times784},\quad b\in\mathbb R^{10}.
\end{equation}
It contains $784\times10+10=7{,}850$ parameters. Despite the name softmax classifier, the implementation returns logits directly. It learns a position-specific linear decision rule without hidden feature interactions, local weight sharing or explicit invariance. Its small parameter count makes it a useful cost baseline.

\subsubsection{Multilayer Perceptron}
The MLP maps $784\to256\to128\to10$. Each hidden layer has ReLU and dropout 0.2; the output layer has neither. Its total is
\begin{equation}
(784\cdot256+256)+(256\cdot128+128)+(128\cdot10+10)=235{,}146\;\text{parameters}.
\end{equation}
Nonlinear activations enable interactions between pixels, but flattening leaves spatial relations to fully connected weights. Dropout regularizes training and is disabled at evaluation.

\subsubsection{Convolutional Neural Network}
Two blocks apply $3\times3$ convolution with padding 1, ReLU and $2\times2$ max pooling. Channels grow from 1 to 32 to 64; feature maps shrink from $28\times28$ to $14\times14$ and then $7\times7$. The head flattens 3,136 features, maps them to 64 hidden units with ReLU and dropout 0.2, and outputs ten logits.

Local kernels and weight sharing encode the assumption that garment patterns are useful at multiple image locations. Pooling builds a coarser feature hierarchy. This structural bias differs from simply increasing dense-layer capacity.

\subsubsection{LSTM: Rows as Timesteps}
The channel dimension is removed to form $X\in\mathbb R^{B\times28\times28}$. There are 28 timesteps, each containing the 28 pixels of one image row. A two-layer, unidirectional LSTM with hidden size 128 processes the sequence from top to bottom. Its gates update a cell state and hidden state using the current row and preceding state. The final hidden state of the last layer summarizes the image; dropout 0.2 and a $128\to10$ affine layer produce logits. Inter-layer LSTM dropout is also 0.2.

For one layer, PyTorch stores input and recurrent weight blocks for four gates, with two bias vectors per gate. Thus the count is
\begin{equation}
\underbrace{4(128)(28+128+2)}_{80{,}896}
+\underbrace{4(128)(128+128+2)}_{132{,}096}
+\underbrace{128\cdot10+10}_{1{,}290}=214{,}282\;\text{parameters}.
\end{equation}
The model can combine information across distant rows, but its sequential computation and row ordering do not explicitly encode a two-dimensional local neighborhood.

\subsubsection{Transformer: Patch Tokens and Self-Attention}
A $7\times7$ convolution with stride 7 projects each non-overlapping image patch to 128 features. The $4\times4$ patch grid becomes 16 tokens, $X\in\mathbb R^{B\times16\times128}$. A learned $1\times16\times128$ positional embedding distinguishes token locations. Each of two pre-normalized encoder layers uses four attention heads of width 32, residual connections, dropout 0.2 and a GELU feed-forward network of width 256. For each head,
\begin{equation}
Q=XW_Q,\quad K=XW_K,\quad V=XW_V,\qquad
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{32}}\right)V.
\end{equation}
Here $X$ denotes the layer-normalized tokens entering an attention sublayer. Queries, keys and values all come from this same image-token sequence. Attention mixes information between patch locations; the combined encoder output retains shape $B\times16\times128$. Mean pooling over tokens, LayerNorm and a $128\to10$ head yield logits. There is no class token or pretrained backbone.

Patch projection contributes 6,400 parameters, positional embeddings 2,048, the two encoder layers 264,960, and the final normalization/head 1,546: 274,954 in total. Attention provides global token interactions but has less built-in local image structure than the CNN. The $7\times7$ patch size also changes how fine spatial details enter the network.

\subsection{Loss and Evaluation Protocol}
\subsubsection{Cross-Entropy and Prediction}
All models minimize unweighted cross-entropy on raw logits~\cite{pytorchloss}:
\begin{equation}
\mathcal L=-\frac1B\sum_{i=1}^{B}\log\frac{\exp z_{i,y_i}}{\sum_{c=0}^{9}\exp z_{ic}}.
\end{equation}
The predicted class is $\hat y_i=\arg\max_c z_{ic}$. Applying softmax before this loss is unnecessary; no additional threshold or post-processing is used.

\subsubsection{Accuracy, Macro-F1 and Class Diagnostics}
Accuracy is $N^{-1}\sum_i\mathbf1(\hat y_i=y_i)$. For class $c$,
\begin{equation}
F1_c=\frac{2TP_c}{2TP_c+FP_c+FN_c},\qquad
\mathrm{Macro\mbox{-}F1}=\frac1{10}\sum_{c=0}^{9}F1_c.
\end{equation}
Accuracy measures the overall proportion of correct predictions, whereas Macro-F1 weights all ten classes equally and accounts for both precision and recall. Metrics use complete prediction/target vectors for each evaluated partition, not averages of batch scores. Validation Macro-F1 selects the checkpoint; test metrics never enter that decision. The metric code explicitly includes all ten labels and uses zero for undefined denominators. Confusion-matrix rows are true classes and columns are predictions. Row-normalized diagonals measure recall, not overall accuracy. Saved error-analysis records include each class's precision, recall, F1 and support, plus the most frequent directed confusions.

\subsubsection{Checkpoint Selection and Comparison Criteria}
After each epoch, a strict improvement in validation Macro-F1 replaces the checkpoint; an exact tie retains the earlier epoch. Checkpoints save model and optimizer states, epoch, validation metrics and configuration. Test evaluation uses that checkpoint rather than necessarily epoch 20. This epoch-level selection rule is distinct from hyperparameter selection and does not establish a tuning history.

The five saved runs form one shared architecture/representation comparison. The following hypotheses organize its interpretation; they are not claimed to have been registered before the experiments:
\begin{itemize}
\setlength{\itemsep}{4pt}\setlength{\parskip}{0pt}
\item \textbf{Nonlinear representations.} MLP is expected to exceed Linear in test Accuracy and Macro-F1 by learning nonlinear pixel interactions. The comparison directly contrasts their two test scores.
\item \textbf{Spatial inductive bias.} CNN is expected to offer a favorable classification-quality--parameter trade-off relative to flattened (MLP), row-sequence (LSTM) and patch-token (Transformer) representations. Assess this separately against each model using Accuracy, Macro-F1 and parameter count; no accuracy-per-parameter ratio is introduced.
\item \textbf{CPU inference cost.} LSTM and Transformer are expected to have higher median CPU forward latency than Linear and MLP under the same benchmark protocol. Recurrent dependencies and projection/attention operations are plausible contributors to cost, but these timings do not isolate or prove their individual effects.
\end{itemize}

Dropout is absent from Linear; the nonlinear models use rate 0.2 at architecture-specific locations. It is therefore not a fully identical control across models.

Higher Accuracy and Macro-F1 indicate better observed classification quality; parameter count and measured times are evaluated separately as costs. The nonlinear-representation comparison contrasts MLP with Linear; the spatial-bias comparison evaluates CNN's quality and parameter count against each alternative; and the CPU-cost comparison contrasts LSTM/Transformer latency with both dense baselines under the fixed timing settings. A quality gain accompanied by higher cost is reported as a trade-off. No composite score, numerical acceptance threshold or new statistical test is introduced. Section~3.3 reports the quantitative comparisons, while Section~3.5 interprets representation and inductive bias.

Conclusions concern these concrete configurations. One seed provides no estimate of variability across independent runs. Equal epochs do not imply equal compute or matched capacity, and simultaneous changes in architecture and representation prevent isolating their causal contributions. No statistical significance or universal architecture ranking is inferred.

\subsubsection{Timing Protocol}
Training time is wall-clock duration of the fit loop, including training, validation, metric computation and checkpoint writes; dataset preparation and model construction are excluded. Inference artifacts record CPU execution, four threads, batch size one, five warm-up passes and 20 timed repeats using \texttt{perf\_counter}. Only the loaded model's forward pass is timed in inference mode. Data loading, preprocessing, checkpoint loading and startup are excluded. The report gives the median; p95 is retained for context. Table~\ref{tab:finalcomparison} in Section~\ref{sec:results} reports measured training and inference times alongside test quality. These are repeated timings of one preprocessed test image, not a distribution over the entire test set or end-to-end deployment latency.

\subsection{Implementation and Verification}
The group implements architecture classes and representation changes, configuration merging, training-only statistics and split checks, training/evaluation control flow, checkpoint handling and diagnostic/reporting scripts. These assemble library components rather than reimplementing numerical kernels. PyTorch supplies affine/convolutional/recurrent/attention layers, autograd, Adam, cross-entropy and DataLoader; torchvision supplies Fashion-MNIST and image transforms; scikit-learn computes classification metrics; Matplotlib/seaborn render plots; and PyYAML reads/writes configurations. All five models are trained from scratch; no pretrained backbone substitutes for a mandatory architecture.

The source test suite includes checks for metrics, weighted losses, training updates, evaluation behavior, checkpoint restoration, deterministic splitting, loaders, transforms, EDA and random-number control. Dataset tests replace downloads with in-memory inputs. Such tests address pipeline behavior; their presence alone does not establish a passing test run or reproduce benchmark accuracy.

For this report, all five stored confusion matrices were used to recompute Accuracy/Macro-F1, the comparison CSV was reconciled with saved metric/timing records, and selected-epoch fields were checked across histories and diagnostic records. These are consistency checks of committed artifacts, not new training or test-set inference runs.
